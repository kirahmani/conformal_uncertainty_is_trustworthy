# Operational Phase Determines Whether Conformal Uncertainty Is Trustworthy in Machine Learning-Based Anomaly Detection for Microservices

Experiment package for the manuscript  
**"Operational Phase Determines Whether Conformal Uncertainty Is Trustworthy in Machine Learning-Based Anomaly Detection for Microservices"**  
(Scientific Reports).

Every table and figure in the manuscript is produced by this code from fixed seeds.

## Reproduce

```bash
pip install -r requirements.txt
cd src
python3 experiment.py        # synthetic matrix, ~10 min -> results/
python3 realdata.py          # real RCAEval telemetry -> results/
python3 analysis_final.py    # tables to stdout, figures/
```

Seeds 1–10, deterministic.

## Layout

| Path | Role |
|---|---|
| `src/phases.py` | Six-phase operational model and synthetic telemetry generator |
| `src/detectors.py` | PCA, Isolation Forest, registry |
| `src/neural.py` | Dense autoencoder and LSTM sequence autoencoder (PyTorch) |
| `src/conformal.py` | Split, rolling, frozen-rolling, ACI, Mondrian; online regime detector |
| `src/experiment.py` | Synthetic matrix: 4 detectors × 2 calibration regimes × 10 seeds |
| `src/realdata.py` | RCAEval replication with block-bootstrap inference |
| `src/analysis_final.py` | Tables, paired tests with Holm correction, figures |
| `data/rcaeval_multisource/` | Real Online Boutique telemetry (RCAEval multi-source release); only `metrics.csv` and `inject_time.txt` are used by the code |
| `results/` | Pre-computed result CSVs underlying all manuscript tables |
| `figures/` | Pre-generated figures (regenerated by `analysis_final.py`) |

PyTorch is required for the two neural detectors. Without it the study still runs
on PCA and Isolation Forest and reproduces the core finding.

## The claim

Split conformal bounds the false-alarm rate on inliers **marginally**, under
exchangeability. Microservice phase transitions break exchangeability benignly:
load ramps, deployments and post-incident recovery contain no fault at all. The
marginal rate can therefore sit at nominal while the rate *conditional on phase*
is an order of magnitude higher, which is what an operator experiences.

Four of the six synthetic phases are fault-free, so every alarm raised in them
is unambiguously false. On the real trace the 720 s before fault injection are
documented fault-free and serve the same role.

## Headline numbers (α = 0.05)

Synthetic, mixed calibration, split conformal, mean over 10 seeds:

| Detector | Marginal FPR | Worst-phase FPR | Ratio | Power |
|---|---|---|---|---|
| PCA (linear) | 0.0510 | 0.4828 | 9.7 | 0.9945 |
| Isolation Forest (ensemble) | 0.0514 | 0.6223 | 12.4 | 1.0000 |
| Dense autoencoder (neural) | 0.0518 | 0.5145 | 10.3 | 0.9969 |
| LSTM autoencoder (sequence) | 0.0511 | 0.9831 | 19.7 | 1.0000 |

Model class decides *where* the failure falls. The LSTM is near nominal during
ramp (0.0089) and deploy (0.0019) where PCA reaches 0.3137 and 0.0492, and
flags 0.9831 of fault-free recovery windows against PCA's 0.4828.

Phase-conditional calibration with a known phase label: worst-phase 0.0635–0.0792
(ratio 1.3–1.6) at unchanged power. With an online-detected regime instead:
no improvement at all.

Steady-only calibration raises the **marginal** rate to 0.302–0.314, voiding the
guarantee outright.

Real telemetry, held-out fault-free windows, marginal FPR against nominal 0.05:
dense AE 0.083, Isolation Forest 0.167, PCA 0.250, LSTM AE 0.533. The ordering
tracks parameters per training sample (214 and 322 for the two neural models
against 60 training windows).

## Important

Three defects in an earlier version of this code were corrected during
preparation and are documented in the audit package: train and calibration sets
were not disjoint; detection power used the wrong denominator; and the unit of
analysis pooled across detectors. Results predating those fixes should not be used.

Synthetic telemetry is generated from a parametric model. The qualitative finding
follows from the structure of conformal calibration; the specific ratios should not
be read as properties of production systems.

## Data

The `data/rcaeval_multisource/` directory contains the subset of the
[RCAEval](https://github.com/phamquiluan/RCAEval) multi-source benchmark
used by this study. Only `metrics.csv` (42 selected channels, 1 Hz, 1441 s)
and `inject_time.txt` are read by `realdata.py`. The remaining files
(`traces.csv`, `logs.csv`, and auxiliary time-series files) are part of the
full benchmark release but are not required to reproduce any result in the
paper. They can be downloaded from the
[RCAEval multi-source release](https://github.com/phamquiluan/RCAEval/releases)
if needed.
